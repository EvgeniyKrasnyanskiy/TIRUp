### 1.2. Развитие модуля ИИ-ассистента (AI Assistant Enhancements)
- **1.2.1. Пул и ротация API-ключей из разных аккаунтов (API Key Rotation)**:
  - **Суть**: Возможность добавления нескольких API-ключей. При исчерпании квоты (HTTP 429) клиент автоматически переключается на следующий рабочий ключ в пуле.
  - **Важное требование к UI**: Чёткое пояснение в интерфейсе, что ключи должны быть созданы в **разных аккаунтах Google**, так как ключи одного аккаунта/проекта делят общий лимит квот.
  - **Архитектура**: Хранение списка ключей в зашифрованном виде (AndroidKeyStore), алгоритм карусели/ротации в GeminiClient с отслеживанием временно исчерпанных ключей.
- **1.2.2. Предупреждение о VPN / Прокси в онбординге**:
  - **Суть**: Добавление наглядной информационной плашки в модальное окно настройки API-ключа с предупреждением о том, что Google Gemini API заблокирован для IP-адресов РФ (ошибка HTTP 400 «User location is not supported»), и для работы требуется активный VPN или прокси.
- **1.2.3. Селектор произвольного диапазона дат (Custom Date Range Picker)**:
  - **Суть**: Расширение панели контекста гликемии — добавление возможности выбора произвольного временного интервала (например, за любые 20, 40, 60 дней) через полноэкранный DateRangePicker.
  - **Архитектура**: Адаптивный расчет шага агрегации и сжатия данных в AiGlycemicContextBuilder при больших интервалах, чтобы не превышать лимиты токенов.
- **1.2.4. Счётчик суточных лимитов и прогресс-бар (Daily Usage Progress Bar)**:
  - **Суть**: Наглядный прогресс-бар расхода лимита (например, «Использовано сегодня: 15 / 1500 запросов») в шапке ассистента или карточке настройки ключа.
  - **Архитектура**: Учёт количества запросов за текущие сутки и извлечение `usageMetadata` (`totalTokenCount`) из ответов Gemini API; локальный сброс счётчика в 00:00 (полночь); мгновенная фиксация 100% исчерпания при получении кода HTTP 429.
- **1.2.5. Рендеринг разметки Markdown в сообщениях чата (Markdown Formatting)**:
  - **Суть**: Преобразование текста модели со стандартной Markdown-разметкой (`**жирный шрифт**`, `*курсив*`, списки и заголовки) в форматированный `AnnotatedString` в Compose вместо отображения сырых звёздочек.
  - **Архитектура**: Лёгкий встроенный парсер Markdown без добавления тяжёлых сторонних библиотек, сохраняющий минимальный размер APK.

- **1.2.6. Долговременная адаптивная память ассистента (Persistent Rolling Memory)**:
  - **Суть**: Сохранение ключевых индивидуальных особенностей пользователя (чувствительность к углеводам в разное время суток, выявленные паттерны, предпочтения в блюдах, важные заметки диалога) между сессиями.
  - **Архитектура**: Компактное скользящее резюме (Rolling Memory Summary) объёмом до ~300 токенов. При накоплении диалога модель обновляет это резюме, перезаписывая устаревший файл памяти, что исключает раздувание контекста и перерасход токенов.

## 🚀 Приоритет 2 (Среднесрочные задачи)

### 2.1. Поддержка носимых устройств (Wear OS & Smartwatch Integration)
- **Суть**: Мгновенный доступ к сахару, стрелке тренда, времени замера и статусу IoB на смарт-часах без необходимости доставать телефон.
- **Архитектурное решение**:
  - **Модуль Wear OS Companion / Tiles**: Виджет-плитка для часов (Wear OS 3+) и циферблатные усложнения (Complications).
  - **Локальный микро-HTTP сервер для часов Garmin / Amazfit / Pebble**: REST-эндпоинт на localhost (порт 17581) в формате JSON для интеграции со сторонними циферблатами.

## 🔮 Приоритет 3 (Стратегическое развитие)

### 3.1. Семейный мониторинг и синхронизация квитирования тревог (Family Alert Sync)
- **Суть**: При наблюдении за пациентом несколькими родственниками отключение тревоги одним из них автоматически отключает сирену у остальных.
- **Архитектурное решение**:
  - Лёгкий протокол взаимного квитирования по локальной сети Wi-Fi/LAN или через push-сигнал Nightscout.
  - Логирование: отображение, кто именно из наблюдателей подтвердил и отключил тревогу.

### 3.2. Автоматическое зашифрованное резервное копирование в облако (Cloud Backup)
- **Суть**: Защита от потери многолетней медицинской истории при смене или поломке смартфона.
- **Архитектурное решение**:
  - Автобэкап по расписанию (раз в неделю) в Google Drive / Nextcloud / WebDAV.
  - Сквозное AES-256 GCM шифрование мастер-паролем пользователя перед отправкой файла.
