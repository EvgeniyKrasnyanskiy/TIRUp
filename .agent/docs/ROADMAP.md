## 1. [Низкий приоритет] Ввод IoB, CoB, BG и заметок с передачей в xDrip+ / Nightscout
> **Примечание**: У пользователя уже есть рабочий виджет, через который данные передаются в xDrip через собственный сервер. Задача переведена в низкий приоритет (возможно, вернёмся к ней позже или откажемся полностью).

- [ ] **Форма ввода лечения** в TIRUp:
  - *Статус исследования архитектуры*: Локальный микро-вебсервер xDrip (порт 17580) работает только на чтение (`GET`) и на внешние `POST /treatments.json` отвечает 500 Internal Server Error. Открытых публичных BroadcastReceiver для инъекций болюсов сторонними приложениями в сборке xDrip нет (и на мастере, и на фолловере).
  - *Реализованный задел*: в TIRUp подготовлен компонент быстрого ввода `TreatmentInputBottomSheet` и `QuickActionStrip` (закомментированы в [FocusScreen.kt](file:///d:/Users/physicist/Desktop/ken/TIRUp/app/src/main/java/com/tirup/app/presentation/focus/FocusScreen.kt)), метод `addTreatment` в `FocusViewModel`.
  - *План реализации (если потребуется в будущем)*: передавать данные напрямую в облачный бэкенд/сервер пользователя (Nightscout REST API `POST /api/v1/treatments`), откуда они штатно синхронизируются и в мастер, и во все фолловеры xDrip.
  - Поля: инсулин (ед.), углеводы (г.), BG вручную (ммоль/л/мг/дл), заметка (текст).
  - Учёт в расчёте CoB и IoB внутри TIRUp.

## 3. Энергоэффективный AOD режим (Always-On Display) для мониторинга сахара
- [ ] **Архитектура AOD внутри TIRUp для AMOLED/OLED без выгорания (Burn-In)**:
  1. **Управление экраном и активность поверх блокировки**:
     - Использование флагов `setShowWhenLocked(true)`, `setTurnScreenOn(true)` и `FLAG_KEEP_SCREEN_ON`.
  2. **Абсолютно черный фон (#000000) и микро-яркость**:
     - Фон `#000000` (физическое отключение 95%+ пикселей матрицы AMOLED).
     - Управление локальной яркостью окна: `layoutParams.screenBrightness = 0.01f` (1% яркости окна без изменения системной настройки).
     - Приглушенные тона текста сахара (темно-серый `#555555`, приглушенный изумрудный `#006600`).
  3. **Событийно-ориентированная логика под 1-минутный CGM**:
     - Экран спящего смартфона полностью гаснет/чернеет.
     - При поступлении нового сахара (каждую минуту или 5 минут):
       - Экран «просыпается» на минимальной яркости на 3-5 секунд.
       - Показывает свежее значение + стрелку тренда в случайно смещенной позиции.
       - Если сахар в норме — возвращается в 0% потребления до следующего замера.
       - Если сахар вышел в зону тревоги (аларм) — запускается импульсный цикл «2 сек показ / 3-5 сек пауза» для привлечения внимания.
  4. **Защита от выгорания матриц (Anti-Burn-In)**:
     - Генерация случайного смещения `Offset(±30..50px)` от центра при каждом показе.
     - Периодическая ротация зон отображения (сверху / по центру / снизу).
  5. **Отсутствие сенсорного взаимодействия в AOD-режиме**:
     - Приглушенный режим блокирует все тапы и жесты. Взаимодействие возможно только после явного снятия блокировки (пароль / отпечаток / двойной тап). (Возможно нужно добавить отключаемую опцию). 
     - Важно: в случае критических тревог (Extra-HYPO / Extra-Hyper) AOD переходит в **активный режим**: экран не гаснет, отображается 50-секундная сирена ГО (или 16-секундный пульсар), пока не будет вручную остановлена или отменена. 
  6. **Энергопотребление AOD**:
     - В режиме **Predictive** и **Low** экран гаснет между замерами.
     - Только в режимах **CRITICAL / SIGNAL_LOSS** экран остается активным с импульсной сиреной (показ / пауза). 
     - Автозапуск этого режима по времени. Много вопросов для обсуждения этого пункта.
