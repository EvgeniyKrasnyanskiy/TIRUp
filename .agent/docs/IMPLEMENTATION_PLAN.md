## Пакет 4: Синхронизация истории, бейдж доступа к файлам и удаление паттернов (<= 3 файлов)
1. **`DexdripBroadcastReceiver.kt`**:
   - Адаптивный расчёт глубины истории при опросе локального веб-сервера xDrip (`sgv.json?count=...`):
     - Если база данных пуста или принудительный опрос: запрашивать полные сутки `count = 288` (288 точек * 5 мин = 24 часа).
     - Если обнаружен разрыв данных (> 5 минут): вычислять точное число пропущенных точек по времени: `((now - lastInDb.timestamp) / 300_000L).coerceIn(12L, 288L) + 2`.
     - Все полученные точки пачкой сохраняются в репозиторий.
2. **`SettingsScreen.kt`**:
   - В карточке автобэкапа:
     - Если `Environment.isExternalStorageManager()` возвращает `true`: показывать аккуратную зеленую плашку-бейдж `✓ Доступ к файлам разрешён` (с возможностью тапа для открытия системных настроек).
     - Если `false`: показывать кнопку с призывом `Предоставить доступ к файлам`.
3. **`TrendsViewModel.kt` & `TrendsScreen.kt`**:
   - В `TrendsViewModel.kt`: добавить методы `deleteArchivedPattern(id: String)` (перманентное удаление паттерна из списка отображения) и `clearArchivedPatterns()` (полная очистка архива).
   - В `TrendsScreen.kt`: в блоке раскрывающегося архива добавить иконку корзины (`DeleteOutline`) рядом с кнопкой восстановления у каждого паттерна, а также кнопку «Очистить архив».

## Пакет 5: Восстановление бэкапа при первом запуске (Онбординг) (<= 2 файлов)
1. **`HelpAndDisclaimerDialog.kt` & `MainActivity.kt`**:
   - В диалог первого запуска/дисклеймера добавить заметную кнопку **«Восстановить историю из бэкапа»**.
   - Подключить лаунчер системного проводника SAF (`ActivityResultContracts.OpenDocument()`) для выбора файлов `.json`, `.csv` или `.zip`.
   - При выборе файла вызывать `AutoBackupManager.restoreFromUri`, оповещать пользователя об успешном импорте и сразу переводить приложение в рабочий режим (`hasSeenOnboarding = true`).
   - Если обнаружены недоступные из-за UID бэкапы в `Documents/TIRUp/Backups`, предложить выдать «Доступ ко всем файлам» в один клик.
2. **Подготовка сборки**:
   - Проверка отладочной сборкой `./gradlew assembleDebug`.
   - Коммит и пуш каждого пакета.
   - Финальная сборка релиза `./gradlew assembleRelease` с установкой на устройство.
