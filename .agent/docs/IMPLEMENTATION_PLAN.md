# План реализации: Энергоэффективный AOD режим (Always-On Display) для мониторинга сахара

## Описание задачи
Реализовать специализированный ночной/автономный режим **AOD (Always-On Display)** для AMOLED/OLED экранов с максимальным энергосбережением (0% потребления экрана между замерами или физический 1% яркости), защитой от выгорания пикселей (Anti-Burn-In), гигантским шрифтом сахара (80–90% экрана), управлением жестами (свайп/кнопки для выхода, двойной тап для экрана-фонарика с плавным 15-секундным нарастанием яркости) и бесшовной интеграцией с системой критических тревог.

---

## Архитектура решения

### 1. Модель данных и настройки (`AodSettings`)
Создать `AodSettings` внутри `UserSettings.kt`:
```kotlin
data class AodSettings(
    val isEnabled: Boolean = false,               // Включен ли AOD функционал в приложении
    val displayMode: AodDisplayMode = AodDisplayMode.PULSE_ON_UPDATE, // PULSE_ON_UPDATE ("Просыпаться при обновлении") или ALWAYS_ON ("Всегда горит")
    val pulseDurationSeconds: Int = 5,           // Длительность показа при обновлении (по умолчанию 5 сек)
    val autoChargeEnabled: Boolean = false,      // Автозапуск при постановке на зарядку
    val autoChargeStartHour: Int = 23,           // Начало интервала ночной зарядки (23:00)
    val autoChargeStartMinute: Int = 0,
    val autoChargeEndHour: Int = 7,              // Конец интервала ночной зарядки (07:00)
    val autoChargeEndMinute: Int = 0
)

enum class AodDisplayMode {
    PULSE_ON_UPDATE, // Черный экран 0%, загорается на 5 сек при новом сахаре или по тапу
    ALWAYS_ON        // Непрерывно горит на минимальной яркости (1%)
}
```

### 2. Экран AOD (`AodActivity` или полноэкранный диалог поверх окон)
Создать `AodActivity` (наследуется от `ComponentActivity`):
- **Поведение окна и блокировка**:
  - `setShowWhenLocked(true)`, `setTurnScreenOn(true)`, `FLAG_KEEP_SCREEN_ON`.
  - Установка минимальной локальной яркости окна: `window.attributes.screenBrightness = 0.01f`.
  - Полноэкранный режим без системных панелей (Immersive Sticky Mode: скрыты NavigationBar и StatusBar).
- **Экран и визуал**:
  - Фон: `#000000` (абсолютный ноль для AMOLED).
  - Приглушенные гармоничные цвета:
    - В норме: приглушенный изумрудно-серый / темно-зеленый.
    - Ниже нормы / гипо: темно-красный / бордовый.
    - Выше нормы / гипер: темно-янтарный.
  - Гигантский индикатор сахара (80–90% ширины экрана) + крупная стрелка тренда + дельта и возраст замера.
  - Кнопка выхода в верхнем правом углу (полупрозрачный крестик ✕).
- **Anti-Burn-In (Защита матрицы OLED)**:
  - При каждом цикле показа (или раз в 60 секунд) смещать контейнер с цифрами по X и Y на случайное расстояние `(-24dp..+24dp)`.
- **Логика отображения (Pulse vs Always)**:
  - В режиме `PULSE_ON_UPDATE`: контент отображается в течение 5 секунд после прихода нового сахара из репозитория (или по тапу пользователя), после чего контент исчезает (экран заливается чистым черным цветом `#000000` с `screenBrightness = 0.001f`).
  - В режиме `ALWAYS_ON`: контент отображается постоянно на 1% яркости со смещением от выгорания.
- **Интерактивные жесты**:
  - **Свайп (вверх/вниз/влево/вправо)** или системная кнопка «Назад» -> выход из AOD.
  - **Одинарный тап в спящем режиме**: пробуждает показ сахара на 5 секунд.
  - **Двойной тап**: режим мягкого ночного фонарика! Плавное нарастание яркости окна от текущей до 100% с заливкой экрана теплым белым светом за 15 секунд (с возможностью мгновенно выключить фонарик повторным тапом).

### 3. Автозапуск при ночной зарядке
- Системный broadcast receiver `PowerConnectionReceiver` (или слушатель в приложении), реагирующий на `Intent.ACTION_POWER_CONNECTED`.
- Проверка: если AOD включен, опция `autoChargeEnabled == true` и текущее время попадает в интервал `[23:00 - 07:00]` -> запускается `AodActivity`.

### 4. Точки входа
- **Кнопка ручного запуска на главном экране (FocusScreen)**:
  - Добавить стильную иконку 🌙 (Ночной AOD) в верхний бар главного экрана (рядом со статусом датчиков / меню).
- **Блок настроек в `SettingsScreen`**:
  - Новая карточка Bento «Энергоэффективный AOD (Ночной монитор)»:
    - Предупреждение/рекомендация: *"Рекомендуется для устройств с AMOLED/OLED экранами"*.
    - Тумблер включения/выключения.
    - Выбор режима: «Просыпаться при обновлении сахара» (0% батареи) vs «Всегда включен» (1% яркости).
    - Настройка автозапуска при зарядке + выбор интервала времени.
    - Кнопка «Запустить AOD сейчас для проверки».

### 5. Интеграция с критическими тревогами
- Если срабатывает `PatientCriticalHypoActivity` (Экран спасения) или критический аларм — `PatientCriticalHypoActivity` открывается поверх `AodActivity` с максимальным приоритетом и яркостью.
- При закрытии тревоги (`finish()`) фокус автоматически возвращается в `AodActivity`.

## Статус этапа: Доработки и исправление падения (Hotfix)

### Выявленная причина падения при запуске AOD:
1. **R8/ProGuard минификация и `by viewModels` в релизной сборке**: В `AodActivity` использовалась ленивая инициализация `by viewModels` с анонимной фабрикой без правил `-keep` в `proguard-rules.pro`. В сборке `release` с `isMinifyEnabled = true` это приводит к `ClassNotFoundException` / `NoSuchMethodException`.
2. **Упрощение архитектуры**: `AodScreen` может напрямую собирать потоки данных (`Flow<GlucoseReading?>`, `Flow<UserSettings>`, `Flow<List<GlucoseReading>>`) через `collectAsState`, не требуя тяжеловесного `ViewModel` с рефлексией.
3. **Безопасная настройка окна**: Обернуть установку `screenBrightness`, скрытие системных панелей (`WindowInsetsController`) и флаги блокировки в блоки `try-catch`, а также обернуть вызов `AodScreen` в `TIRUpTheme(darkTheme = true)`.
